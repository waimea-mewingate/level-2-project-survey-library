# Project Requirements

## Identified Problem or Need

My project will attempt to solve the problem of keeping track of survey instruments / avoiding job overlaps that require the use of said instruments.

## End-User Requirements

My end-users are my dad and his workmates at Newton Survey. 
I talked to my dad about what he wanted from this project, and I got this response: 
"I want to be able to, while I'm on the phone, open up the website and immediately be able to see whether the instrument is free for the job being requested- and if not, whether the timeslot booked by someone else is negotiable. I want to be able to tell my clients straightaway whether I can do their requested job or if it will be later."
Based on this answer, my priorities are:
- Ease of navigation (get to scheduling easy)
- Information layout- allowing specific attributes to be viewed at a glance.


## Proposed Solution

I intend to create a system that allows the end-users to schedule the use of and check the status of survey instruments. It should be as simple as possible. I will keep this system targeted at their workplace specifically as it will be using data from instruments of a combination that maybe only their workplace has. 


# Relevant Implications

## Usability

How easy to navigate and use the system is to anybody while minimising confusion and frustration.

### Relevance to the System

This is relevant as systems that are confusing or hard to navigate will reduce the ability for users to use the system and may mean that this project will have no value (doesn't perform).

### Impact / Considerations

To make the site easy to use, I will need to consider:
- layout and system navigation- keeping buttons and information clear and consistent
- limit information on any one page to a minimum
-keep things to a few pages- most functions accessible either on the home page or through a single button.
- add feedback where possible. 


## Accessibility

How useable the site is for people regardless of their abilities or device type.

### Relevance to the System

This is relevant as my users will likely be using a variety of devices like their desktop PCs and their phones, and the workplace also contains two people that are colour-blind, including my dad!

### Impact / Considerations

To increase the accesssibility of my site, I will need to consider:
- my colour scheme- keeping it minimal (black/white with a single highlight colour?) 
- contrasting dark with light to keep things clear for the colour-blind users. 
- keep my site sectioned using semantic HTML tags to allow for device transition and any shuffling that might come with varied screen sizes. 


## End User

How much the system is built with those that will use it in mind- their needs. 

### Relevance to the System

This is relevant because the system must function for its intended uses while still being easy to use. Otherwise, I have made a project that does not fill the intended requirement and (likely) will not end up being utilised.

### Impact / Considerations

I plan to meet the end-user needs by:
- getting feedback as much as I can- making sure I stay on track. From this, I can glean information on what functions need priority, and can act accordingly. 
Also: 
- keep the site simplified- using icons etc instead of blocks of text.


## Functionality

Creating a system that works.

### Relevance to the System

Systems that don't work are useless! Systems that are slow or broken are frustrating and hinder the success of the project.

### Impact / Considerations

To adhere to the heuristic of functionality, I will need to:
- test every function (buttons/forms) as they are added and improved upon to make sure that they work as they should.
- test my site on different devices.


## Aesthetics

The visual design of the system.

### Relevance to the System

Having an aesthetic suited to the task is important for user experience, and consistency with styling is needed to avoid confusion.

### Impact / Considerations

To improve aesthetics, I will need to keep in mind:
- a limited palette 
- simple, clean layout as much as possible while keeping main aspects the same across pages. 

This will also be needed to be considered in tandem with accessibility- 
- Using a colour palette of black/white/grey with an accent colour (yellow? Most colour-blind people can see yellow)? 
- thinking more about light and dark than colour, making sure to contrast greyscale values (dark on light always or light on dark).
